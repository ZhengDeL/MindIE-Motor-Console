# 离线功能指南

“功能配置 → 配置说明”直接显示配套指南，包含用途、前置条件、可复制的原生配置或命令、平台操作步骤、验收证据和回滚。无需访问文档网站，也不自动修改模板或服务。

内容与 `mindie-motor/upstream` 固定提交 `37d615f232a36b8dba8630ffc3a01a20d289c65e` 对齐。`web/backend/capability_guides.json` 保存 21 项结构化记录，`capability_guides.py` 只读取该固定包内文件；HTTP 请求不能指定路径、下载地址或执行代码。`/api/meta` 中每项能力的 `guide` 提供数据，前端按固定 schema 渲染纯文本与代码，不解析任意 HTML。

指南仅在实际 Motor profile 的源码提交与指南记录一致时提供。Motor 独立升级后若尚无对应指南，原能力目录继续展示，但不投影旧版本示例；界面明确提示升级配套指南，避免把旧字段误用于新引擎。这不改变 Motor 升级或原生配置保存机制。

示例均标注目标文件与适用范围。JSON 是合并到完整 `user_config.json` / `env.json` 的增量，不是可直接覆盖整份文件的部署包。示例地址使用文档保留网段，模型名、路径、角色计数和外部依赖须按实际环境补齐。复制不会触发保存、预检、部署或重启。平台保存配置修订也不会调用原生 `deploy.py --update_config`；当前没有专用热更新执行入口。指南中涉及的原生热更新条件是原生能力说明，不能据此判断受管服务已应用该变更，详见[原生配置与入口范围](NATIVE_INTEGRATION.md#原生配置与入口范围)。

Kubernetes Operator、外部指标、CRIU、共享存储、Conductor、池化后端、密钥服务等依赖会逐项列出。默认生效的能力、POC、Docker 入口未接通和额外组件需管理员准备等边界明确区分。配置可解析、预检通过、容器运行、真实特性验收是不同证据；操作者仍需在目标环境完成对应 NPU、负载与故障注入验收。

维护指南时，先检查固定版本文档、配置解析与实际消费代码；修正参数路径并补充对应本地源码路径，保持其他原生字段不变。更换上游版本时应作为独立适配迭代重新核对全部记录。第三方许可证与来源说明保留原样。

`MOTOR_DOCUMENTATION_URL` 默认为空，相关外部文档入口隐藏。配置专用文档地址只会增加可选链接，不影响离线指南，也不会由服务端联网抓取内容。
