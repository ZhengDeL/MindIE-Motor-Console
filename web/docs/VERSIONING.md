# 版本、制品与兼容规则

平台版本、接口合同、数据库和原生 Motor 分别演进。部署及升级时记录各自身份，不把单个版本字符串作为整套系统兼容的证明。

## 需要记录的身份

| 对象 | 核对方式 | 作用 |
| --- | --- | --- |
| 平台源码 | Git 标签或提交、`/api/meta` 的版本及产品标识 | 对应本次构建的源码及文档。 |
| 容器制品 | 镜像架构、不可变摘要、OCI 版本和源码修订 | 确认实际运行的二进制，不能只核对可移动标签。 |
| Agent 合同 | 管理/操作协议、Agent 版本、受支持运行时与能力上报 | 判断能否执行当前控制面的具体操作。 |
| 数据库 | 产品身份、后端、schema 与备份格式 | 决定迁移、写者锁、备份及恢复方式。 |
| 原生 Motor | 固定提交、源码完整性、适配画像 | 确认配置与 deployer 的实际来源。 |
| 推理镜像 | 镜像摘要及其中的 Motor、引擎、CANN 等版本 | 决定运行时实际能力；固定 deployer 不等于镜像内包版本。 |
| 插件 | 包格式/API、插件版本、宿主/依赖范围、精确 SHA-256 | 控制导入、装配和旧制品选择；摘要不是作者签名。 |

## 发布通道与开发能力

当前开发版本与源码获取方式见[项目首页](../../README.md#获取源码)，已发布版本见[Releases](https://github.com/ZhengDeL/MindIE-Motor-Console/releases)。版本字符串、源码提交与实际 SDK 能力同时核对；插件能力通过已登录控制面的 `/api/plugin-sdk` 查询。

`/api/meta` 可提供平台元信息，不能代替功能探测。`/api/plugin-sdk` 返回401时先登录；没有该入口或返回不支持的合同版本时，不向旧系统导入包。执行 Agent 不是控制面插件管理入口。

公开主线为 `main`，可复现安装固定已发布标签或审核后的提交。发布源码、构建镜像、发布受信升级清单及更新服务器分别进行；GitHub 创建标签不会自行重启部署。

## 原生适配

当前默认原生提交固定为 `37d615f232a36b8dba8630ffc3a01a20d289c65e`，不在部署过程中跟随上游主分支更新。镜像标签或源码内包版本不能替代提交身份；准确关系见[原生集成](NATIVE_INTEGRATION.md)。

原生配置的未知 JSON 字段需要保留。新版本若改变入口、端口、认证、清单或运行语义，应建立并验证对应适配画像，再选择其使用范围；不能靠改镜像名称或取消兼容校验强行接入。

## 升级与回退

升级前核对平台、Agent、数据库和模型服务的兼容组合，保留镜像、部署配置及恢复材料。数据库和 Agent 账本按各自合同备份；社区包制品与私有选择配置还需要独立备份。

插件选择在下次启动生效，回退使用相同 ID 的已导入旧摘要。回退代码不自动还原插件业务数据。升级后多个旧插件均不兼容时，使用带修订保护和私有快照的包恢复命令，不手工删文件或关闭身份保护。

验证应说明使用的源码/制品、操作、环境及边界。界面、接口合同、容器、真实 Agent、模型推理及长期运行分别验证；历史发布记录不代表任意新组合已经通过。
