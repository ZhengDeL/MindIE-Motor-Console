# 服务指标接口

`GET /api/services/{service_id}/metrics` 读取指定服务的指标。接口沿用控制台会话鉴权，系统管理员、运维操作员和只读用户均可读取；不接受调用方提供目标 URL，不执行推理、部署或资源修改。

指标读取要求服务对应运行时插件可用。此接口提供当前短期快照；需要跨会话历史、主机/NPU 趋势或告警时，应使用独立 [Prometheus/Grafana 观测模块](../observability/README.md)。模型指标和硬件观测的来源、维度及有效期分别处理。

## 返回字段

| 字段 | 含义 |
| --- | --- |
| `service_id` | 当前服务 ID |
| `revision` | 配置、部署任务、生命周期及执行节点连接信息的修订摘要；变化后客户端须重建速率基线 |
| `state` | `ready`、`warming`、`unavailable`、`stale` 或明确标记的 `demo` |
| `metrics_view` | Docker 为 `dp`，Kubernetes 当前兼容路径为 `full` |
| `metrics_text` | 原生 Prometheus 文本；本次失败、修订失配或过期时不作为当前采样返回 |
| `sampled_at` / `expires_at` | 读取完成时间及有效期；缓存读取不延长有效期 |
| `cache_hit` | 本次是否复用已有采样或采样状态 |
| `interval_seconds` | 同服务最短采样间隔，当前为 10 秒 |
| `error` | 无有效采样时的可读提示，不包含原始异常中的凭据或目标地址 |

草稿、已停止、正在执行生命周期操作、无受管资源或存在尚未应用配置的服务不发起指标连接。演示环境只返回明确的演示状态，不生成假的真实指标。

## Docker 与 Kubernetes 的统计粒度

Docker 直接读取配置中的 Coordinator 原生 `/metrics?type=dp&format=prometheus`。`dp` 视图保留 `instance_id`、`dp_rank`、`role`、`pod_ip` 等序列标签。客户端按完整序列分别比较累计值，遇到序列集合变化、计数回退、修订变化或不连续采样时重建基线，避免先汇总再求差分掩盖单个端点的计数回退。

Kubernetes 复用现有执行 Agent 的 `/agent/kubernetes/observations?service_id=...` 只读契约，其中的指标是原生 `full` 视图。该兼容路径未增加 Agent 接口或改变原生端口转发逻辑。`full` 已汇总端点，客户端只能发现汇总序列变化或整体计数回退，不能保证识别被其他端点增量抵消的单端点回退。界面和调用方应保留此粒度说明，不将其表述为完整端点级重启检测。

两条路径都统计引擎计数。P/D 阶段可能分别计数，完成计数和速率不等于用户请求量或用户请求 QPS。原生报告的 Motor 计算速率仍保留在原始文本中，平台趋势不直接将这些速率当作全服务总量。

## 开销与失效规则

- 按需读取，没有永久后台指标采集器；浏览器离开页面或隐藏后不持续轮询。
- 同服务共享至少 10 秒采样间隔和单飞读取；全局最多 8 个并发读取，不排队堆积。缓存最多 64 个服务，且不会通过淘汰最近采样绕过间隔。
- Docker 使用既有 HTTP 客户端的 3 秒超时/响应体时间预算；Kubernetes Agent 使用 5 秒超时。底层慢响应头的绝对总时限不是本接口已保证的能力。
- 每次响应最多 2 MiB，超限明确失败；不会静默降级到丢失端点身份的视图。
- 有效期为 20 秒。刷新进行中可复用同修订、仍有效的旧采样；刷新失败后当前结果置为不可用，不把旧值或缺测当作 0。
- 趋势只保留浏览器本次查看期间的有限窗口，不是跨会话持久历史或完整 Prometheus/Grafana 系统。
