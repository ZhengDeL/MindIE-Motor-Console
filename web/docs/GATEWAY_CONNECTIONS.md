# 网关连接与服务直连

“网关接入”管理已经存在的 OpenAI 兼容 API 连接。保存连接、绑定推理服务以及检查模型列表，都不会安装独立 AIGW、修改网关路由或启动模型。独立网关的软件、路由和访问认证需要由网关自身配置。

使用前应启用网关插件并具有相应管理权限；插件可用性与外部网关健康是两回事。服务直连与已有网关的部署边界见 [原生集成](NATIVE_INTEGRATION.md)。

## 按表单填写

以下为文档示例地址，请替换为实际地址。

| 表单项 | 已有独立网关示例 | 原生 Coordinator 直连示例 |
| --- | --- | --- |
| 网关名称 | 生产推理网关 | 模型服务直连 |
| API 基础地址 | `https://gateway.example.com/v1` | `http://192.0.2.20:19225/v1` |
| API Key | 填写网关发放的访问凭据；无认证则留空 | 未开启认证时留空 |
| 绑定推理服务 | 勾选应由该网关提供的服务 | 勾选该 Coordinator 所属服务 |

基础地址填写到 `/v1`，不要填写 `/models` 或 `/chat/completions`。检查时平台会追加 `/models`；若网关使用其他 OpenAI API 前缀，填写其实际基础地址。

携带 API Key 的连接必须使用 HTTPS。不能将平台管理员密码、Agent Token 或 SSH 密码填入网关 API Key。凭据保存后不回显，导出连接描述也不包含凭据。

创建连接时，可展开“填写示例与接入说明”，选择一个已经运行并提供有效 API 地址的服务，再点击“填入服务直连示例”。示例只填写表单，不会自动保存或发起网络请求；已有填写内容时会先询问是否替换，并明确提示将清空已填写的 API Key。

原生 Coordinator 可以直接提供模型 API，但它不等于已经安装独立 AIGW。已有外部网关时，必须填写外部网关地址；不能通过勾选服务来替代网关的路由配置。

## 允许检查该地址

保存连接之后，部署管理员需要允许控制台访问这个明确的服务器来源。来源由协议、主机和端口组成，**不包含 `/v1` 等路径**。

例如部署环境变量：

```dotenv
MOTOR_GATEWAY_ALLOWED_ORIGINS=https://gateway.example.com,http://192.0.2.20:19225
```

实际部署可只允许需要的地址。已有其他授权来源时，追加到现有配置，不要覆盖原来的条目。不要使用通配授权或关闭目的地址检查来绕过限制。

Docker Compose 部署在生产环境文件中配置 `MOTOR_GATEWAY_ALLOWED_ORIGINS`，并由部署管理员使控制台配置生效。无需重启模型或 Agent。此设置不会由网页上的“保存连接”自动修改。配置生效后刷新“网关接入”，再点击“检查连接”。

HTTPS 网关必须具有可信证书。使用内部 CA 时，由部署管理员配置并只读挂载 CA 文件，通过 `MOTOR_GATEWAY_CA_BUNDLE` 指向该文件；不应跳过证书校验。

## 检查结果怎么看

| 页面结果 | 含义与处理 |
| --- | --- |
| 检查地址尚未授权 | 展开配置方法，按页面给出的准确来源追加部署允许清单；路径不要带 `/v1` |
| 模型已匹配 | `/models` 返回的模型列表包含绑定服务配置的模型 ID；尚不代表推理请求完整验收通过 |
| 已读取模型 | 已读到模型列表，但未绑定服务进行核对 |
| 存在缺失模型 | 核对网关路由、对外模型别名及绑定服务的模型 ID；模型名称需准确匹配 |
| 读取未成功 | 核对地址、网络、认证和 TLS；使用 HTTPS 认证连接时检查网关凭据与 CA |
| 配置已变更，需重新检查 | 连接或绑定服务配置发生变化，之前的检查结果已失效 |

检查操作只读模型列表，不会发送推理请求。确认模型匹配后，应使用对应 API 入口发起实际推理验收；删除连接只移除平台记录，不会停止网关或模型。
