# MindIE-Motor Console 0.11.0（历史版本）

本页记录已经发布的 `v0.11.0`。该固定标签保留首发时的默认显示名称；统一显示名称的修订见[0.11.1 发布说明](RELEASE_0.11.1.md)。本文更新说明文字不改变旧标签、镜像、数据库或实际运行实例。

本页说明 0.11.0 正式源码的发行范围。`main` 为正式维护入口；安装和升级须核对实际源码提交、构建镜像摘要与运行实例，不以分支名或界面版本号代替制品身份。使用方法见[部署入口](../DEPLOYMENT.md)和[版本规则](VERSIONING.md)。

## 本版内容

### 受信社区插件包

管理员可以在控制面导入离线 `.qhplugin` 源码包，查看清单与精确 SHA-256，明确选择受信版本。导入只做归档、路径、Manifest、完整性和兼容检查并暂存文件；选择按当前修订执行 CAS 保存，均不立即执行插件入口。下次 Control 启动才读取选择、校验依赖并装配。

包摘要标识制品字节，不是作者签名或安全认证。Python 插件与控制面共享进程权限，只能安装经过审查的受信代码。演示模式和执行 Agent 不加载上传的控制面代码；当前不提供在线市场、安装钩子、任意远程 JavaScript、WebSocket 或热卸载。

首次正式提供社区导入的宿主版本为 0.11.0。目标实例仍须在已登录会话通过 `/api/plugin-sdk` 核对 `community-import-v1`、`http-routes-v1` 和所需页面能力，避免前后端或不同制品混用。

### 明确的宿主合同

内置模块和社区插件通过清单、依赖、路由归属及精确版本接口装配。插件通过 `provide/consume` 共享声明的接口，以 `on_shutdown` 登记同步清理。缺失、循环、停用或版本不兼容的依赖会使启动失败；装配失败和正常退出均尝试清理已登记的资源，不自动重试未知外部副作用。

身份、会话、RBAC、CSRF、审计、资源归属和部署准入保留为宿主合同，插件不能声明接管这些端点。存储在早期 bootstrap 选择，SQLite/PostgreSQL 仍使用独立存储适配契约；社区 HTTP 插件不能在工厂装配末尾替换运行中的数据库。

### 声明式界面与离线 SDK

插件可以在自己的 `/api/plugins/<id>` 命名空间挂载受保护 HTTP API，并通过 Manifest 声明导航入口。当前页面合同为 `status-table-v1`：宿主读取结构化列和行，按文本渲染，统一处理登录、角色、加载与失败状态，不执行返回内容中的 HTML 或脚本。

源码提供离线 Manifest/Page Schema、公开 Context 类型合同和 `community-status` 完整示例。插件版本、最低宿主版本、可选不兼容上界及依赖版本分别检查；新增包需要贡献者说明权限、网络/文件副作用、清理与数据迁移。接口和操作步骤见[开发指南](../PLUGIN_DEVELOPMENT.md)、[宿主合同](../backend/plugin_host/README.md)与[包格式/恢复](../backend/plugin_host/packages/README.md)。

### 公开文档与架构

文档按部署、使用、监控、维护和贡献者入口重新组织，提供独立架构图、实际原生部署链、能力矩阵和逐项配置指南。公开说明不包含客户环境、账号、数据库或私有验收日记；第三方来源及许可仍保留。

界面沿用既有运维控制台的列表、详情、主题与品牌设置，复用宿主导航和受控插件页面，不增加独立的远程前端运行时。界面规范及第三方来源见[设计系统](UI_REFERENCE.md)。

平台版本、插件宿主 API 和插件自身版本独立演进。内置模块版本随平台版本上报；第三方包若将宿主或某个内置依赖的不兼容上界设为 `0.11.0`，在本版会按设计拒绝装配。应由作者审查后发布兼容包，不能自动放宽旧包边界或修改已导入制品的字节。

Motor 固定源码、镜像标签和容器内包版本仍分别记录。Docker 保留原生 helper 加 Docker SDK 的执行链、设备账本和操作回执；Kubernetes 保留原生 dry-run 清单及 UID/resourceVersion 保护的执行链，**尚未适配为原生云原生部署 Job**。固定 Docker 入口缺少 Encode，EPD 执行仍明确拒绝；其他高级能力和外部依赖见[原生集成](NATIVE_INTEGRATION.md)与[能力矩阵](NATIVE_CAPABILITY_MATRIX.md)。

平台可以保存和修订完整原生字段，但当前没有专用的原生热更新执行入口；保存修订不会自动执行 `deploy.py --update_config`。本版也没有接入 `msctl` / `ms_server`，`motor-cli-v1` 表示固定 Python deployer/helper 适配。原生配置通道不等于这些维护接口已经接通，具体范围见[原生集成](NATIVE_INTEGRATION.md)。

## 升级、备份与回退

升级前保留控制数据库的一致备份、独立解密密钥、TLS、部署配置、旧镜像摘要、Agent 数据及模型配置。社区插件目录 `MOTOR_PLUGIN_DIR` 不在 Control 应用归档白名单中；即使位于数据目录下，也要独立备份包库、精确摘要、私有选择配置和插件自有数据。不要把这些内容提交到 Git。

选择旧包摘要并重启可回退插件代码，不会自动恢复插件自己的数据迁移。升级后若选择集阻止宿主启动，可使用带修订保护和私有快照的 `reset-selection` 离线恢复命令；它不执行包代码，不删除模型，也不回退数据库。依赖、恢复步骤和存储权限见[包管理说明](../backend/plugin_host/packages/README.md)。

停用页面或插件不会停止已运行的模型、撤销已写入的原生配置或回收设备。停用运行时前应处理管理交接，后续需要管理相应资源时须恢复匹配的运行时合同。

## 交付与验证范围

本版发布源码、配置、离线 Schema、示例和使用说明。GitHub 源码归档及本次平台源码 ZIP 不展开原生子模块；附件 `SOURCE-MANIFEST.json` 记录平台提交、原生 gitlink 与平台文件校验和，不表示包含完整离线构建依赖。完整构建输入应按部署入口递归克隆并核对固定 submodule。实际 API/Web/Agent 镜像仍需要针对架构构建、核验来源和真实摘要；系统维护使用的受信签名升级清单与 GitHub 源码发布是不同材料，示例中的占位摘要须替换后才能用于实际安装。

部署方应逐项验证登录及角色、插件导入/选择/冲突、重启装配、声明式页面、失败清理、停用/旧摘要回退、数据库备份与 Agent 连接。模型部署还需验证原生角色就绪、普通与流式请求、日志、停止和恢复。

文档检查、界面演示和包合同不替代容器、真实 Agent、NPU/Kubernetes、外部 CCAE/Kafka/AIGW、性能或长期运行验收。发布源码不会自动更新服务器、推理镜像、模型权重、Exporter、驱动或集群分配，不改变原生 Motor 的算法和配置语义。
