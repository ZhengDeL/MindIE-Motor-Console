# MindIE-Motor Console 0.12.0

本版发布可替换的业务提供者与完整 UI 插件能力。安装使用固定标签 `v0.12.0`，源码身份与逐文件摘要由发行附件记录；源码、镜像、原生 Motor、插件和运行实例分别管理。

## 主要内容

- **Python Provider SDK**：49 个公开合同覆盖存储、秘密、身份、会话、权限、审计、日志、任务、Agent 连接、采样、资源、Motor 适配、运行时和业务 API。存储在开库前从独立装配文件选择，不局限于 SQLite；新数据库须实现完整事务、条件写、备份与恢复合同。
- **完整 UI SDK**：137 个插槽覆盖外壳、登录、页面、页签、组件、弹窗、动作、按钮、图标、主题、通知及语言。预构建 `.mcui` 支持导入、审查和下次启动选择，无需重新构建宿主；完全未选择默认 UI 时不导入默认 App 和业务样式。
- **Node 插件入口**：公开契约、精确提供者绑定、制品整树摘要、依赖图、生命周期和离线恢复。默认 HTTP 传输与 Python bridge 是普通插件，可由独立处理器替换；原始 HTTP 转发保留 JSON 大整数、未知字段及 SSE 字节。
- **插件管理与恢复**：`.mcprovider`、`.mcui` 和 Node 制品分别校验，不运行安装钩子或自动下载依赖。导入不执行代码；明确选择后重启生效，保存选择不等于已运行。保留 `.qhplugin` 增量社区 SDK，格式与完整 Provider/UI SDK 不互换。
- **一致性与授权**：请求固定提供者/UI 代次，旧代次写入在副作用前拒绝。内核直接调用所选会话和权限合同；账号管理、公共只读入口、CSRF、Agent 身份和关键审计不依赖替代路由自行补充检查。
- **界面回归**：保留现有操作布局和外观；修复首次弹窗焦点恢复及详情页样式加载顺序问题。插件选择、信任与需重启状态分别展示。

操作入口：[插件扩展面](../PLUGIN_EXTENSION_POINTS.md)、[导入与部署](PROVIDER_PLUGINS.md)、[Python SDK](../backend/provider_host/README.md)、[UI SDK](../frontend/sdk/README.md)、[Node SDK](../../platform/README.md)。

## 设计与兼容边界

业务与 UI 的默认实现可以由满足合同的第三方实现替换。制品校验、装配、依赖解析、生命周期、强制检查及失败诊断属于最小宿主；Python 根 ASGI 装配不开放覆盖。完整替换合同不表示任意新协议、新扩展点或新数据结构无需升级 SDK。

这些替换点不等于所有参考业务实现已经拆成独立发行包。当前 `default_console.py` 仍集中组织参考服务工作流和任务辅助逻辑；固定 v1 契约目录之外的新合同需要扩展宿主 SDK。UI SDK 的部分 props 仍从项目组件类型推导，仍需进一步整理独立 DTO、兼容性门禁和开发工具。开发者目前以源码 SDK、公开合同及示例为入口，不能据此假设任意模块均可零适配替换。

插件是经过操作者审查和明确信任的代码，不是沙箱。Node/Python 同进程插件和同浏览器上下文 UI 不提供恶意代码隔离；摘要标识内容，不等于作者签名。当前不提供任意热卸载、自动跨数据库迁移或多实例高可用。

原生 Motor 继续固定 `37d615f232a36b8dba8630ffc3a01a20d289c65e`，本版不改原生请求调度算法、配置语义或推理数据面。产品身份 `motor-console`、Agent/操作协议 1、最低 Agent 0.10.1、数据库 schema 2 与保留的增量插件格式保持兼容。平台源码版本、Node 包版本、SDK 版本与第三方包版本独立演进，不能统一改成同一个数字。

Node 与现有 Python/浏览器 SDK 分层；使用 `compose.plugins.yaml` 时为 Web → Node → 私有 Python worker。已有独立 Web/API 安装仍可使用 Python/UI 提供者，不要求同时引入 Node。集群、网关、Grafana、CCAE 和原生高级能力的实际边界见[原生集成](NATIVE_INTEGRATION.md)与[能力矩阵](NATIVE_CAPABILITY_MATRIX.md)。

| Linux ARM64 隔离运行 | 初始化 172 项、插件选择重启后 194 项断言通过，275 个冻结文件双端 SHA-256 一致；断言包括静态资源字节和响应头，不等于 366 个独立业务功能。实际验证独立 API/UI 插件替换、权限、CSRF、旧代次、静态资源及深链接。 |
| 部署边界 | 独立 API 在无静态目录时启动检查、Compose 配置与 `nginx -t` 通过；44 个适用 Linux 锁定依赖版本匹配，465 个原生文件完整性一致。 |

Linux 验证使用固定既有 API 基础镜像、校验过的官方 Node ARM64 二进制和最终源码 COPY 层构建隔离镜像；**不是标准生产 Dockerfile 的完整供应链构建验收**。本轮没有重新执行真实 NPU/Kubernetes 模型部署、生产 TLS、外部系统、压力或长稳验收，也没有验证任意第三方数据库的真实迁移与恢复。独立插件示例能运行不等于第三方生态已经成熟。

项目提供源码 SDK、合同目录、导入工具和参考插件，开发者可以据此开发与验证。当前 SDK 尚需持续积累跨版本兼容案例、外部开发者反馈和更多自动化贡献工具；本版不作“业界最优”“完美”或“任意插件天然生产可用”的承诺。

## 安装、升级与附件

从[安装指南](INSTALLATION.md)和[提供者部署](PROVIDER_PLUGINS.md)选择拓扑，按目标架构构建并记录真实镜像摘要；示例占位摘要不能直接用于生产。GitHub 源码 ZIP 不展开原生子模块，不包含 Git 元数据、依赖、镜像、凭据、运行数据库或测试产物。完整构建输入应递归克隆固定标签，并核验原生 gitlink。

发行附件包含平台源码 ZIP、逐文件 `SOURCE-MANIFEST.json` 和 `SHA256SUMS`。维护者可用校验和验证字节，并将源码清单中的提交与固定标签对照；这些附件不是部署系统使用的签名镜像升级清单。

更新前保留一致数据库备份、独立密钥、TLS、部署配置、Agent 账本、插件制品与选择文件。排空管理任务后切换；关键存储/执行提供者变更仍检查受管资源和未知结果，代码回退不会撤销远端操作或自动还原插件数据迁移。发布源码不会更新已有服务器、模型、驱动或 Exporter。
