# MindIE-Motor Console 0.11.1

本文对应 0.11.1 候选源码。正式标签及制品发布前，验证以已审核的源码提交为准；现有 `v0.11.0` 保持原样，不通过移动旧标签更新内容。安装与维护步骤见[0.11.1 部署说明](DEPLOYMENT_0.11.1.md)。

## 名称与界面

默认名称统一为 **MindIE-Motor Console**，覆盖登录页、导航栏、浏览器标题、API 元信息、镜像标题、CLI 帮助、证书显示名称及插件 Schema 描述。英文长名称在窄侧栏和小屏登录页可自然换行。

已保存的自定义品牌继续由管理员管理。需要使用新版默认名称时，在“系统设置 → 平台品牌”恢复默认并明确保存；升级不会覆盖用户的自定义名称或图标。

## 安装与发布校验

- 发布清单签发端与读取端共用结构校验，拒绝全零占位镜像摘要、错误类型、产品不匹配及非法版本/兼容范围。读取端仍先验证受信发布者签名；合法摘要也需要核对真实镜像来源、架构及运行效果。
- HTTPS 安装预检核对证书与私钥、有效期、目标域名/IP 的 SAN 和服务端用途，拒绝使用 CA 证书充当服务端身份。观测准备器与控制面准备器复用同一校验；失败时不会创建新的安装数据或环境文件。
- 部署 origin 拒绝缺失主机、空用户信息及空白字符等无效输入，避免生成无法使用的访问配置。
- 补齐 PostgreSQL 驱动在 Windows 所需的条件依赖 `tzdata` 及发行文件哈希，支持完整的哈希锁安装；Linux 的有效锁定依赖保持不变。

证书身份预检不建立客户端 CA 信任，也不执行真实 HTTPS 握手或启动容器。部署方仍需分发受信证书链并验证实际入口。

## 开源使用与兼容

文档、部署示例和插件开发入口统一使用当前产品名称，源码示例目录为 `web/deploy/motor-console`。贡献指南补全本地提交、Fork 与 PR 步骤；安全问题可通过仓库[私密漏洞报告入口](https://github.com/ZhengDeL/MindIE-Motor-Console/security/advisories/new)提交。

| 对象 | 0.11.1 范围 |
| --- | --- |
| 技术产品标识 | 保持 `motor-console` |
| 管理/Agent 协议 | 保持 1；最低 Agent 版本仍为 0.10.1 |
| 数据库 schema | 保持 2，不因显示名称变更迁移数据 |
| 社区插件 | API 1、Manifest schema 1、`status-table-v1`；按实际宿主能力与包的版本范围检查 |
| 原生 Motor | 保持固定提交 `37d615f232a36b8dba8630ffc3a01a20d289c65e` |
| 既有部署与观测标识 | 保留 Compose 项目、存储路径、Grafana UID、Prometheus 序列和已发布 Schema ID |

显示名称与持久化标识分别维护。不要为更名另起 Compose 项目、清空数据库或重新部署 Exporter；它们会改变资源归属或历史查询。原生执行、`msctl` 和热更新的实际支持范围见[原生集成说明](NATIVE_INTEGRATION.md)。

## 升级与验证

升级前保留一致数据库备份、外部解密密钥、部署环境、原 Compose 文件栈、Agent 账本及插件目录。按受审的维护计划更新 API/Web，检查实际版本、默认/自定义品牌、三角色权限、节点连接和原操作回执。失败按原镜像与配置回退，不能用重新初始化代替恢复。

源码包、镜像、已签名升级清单和服务器运行状态分别管理。源码检查、浏览器和隔离准备器验证不替代目标 Linux 容器、受信 HTTPS、模型推理、外部系统及长期运行验收；发布源码不会自动更新服务器。
